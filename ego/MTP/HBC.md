**Why this matters architecturally:** this is precisely why Qualcomm's pitch avoids the expensive HBM-style interposer in the first place — HBC's value proposition is eliminating the power cost of moving data across an interposer to HBM, by putting memory close to whichever compute die needs it (CPU or accelerator) locally. Each compute die (CPU or accelerator XPU) gets its own local HBC memory stack directly on top of it via through-silicon vias; the CPU and accelerator boards then connect to each other at the rack/fabric level (PCIe/CXL/UALink/optical), not via a shared silicon interposer the way a monolithic HBM+GPU package would. [ServeTheHome](https://www.servethehome.com/qualcomm-investor-day-2026-data-center-announcements-cpus-ai-accelerators-and-more/)

So: accelerator + its DRAM = one stack. CPU + its own optional DRAM = a separate stack. CPU and accelerator are disaggregated at the rack level, not co-packaged on one interposer.
